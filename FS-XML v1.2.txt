
Спецификация формата управления файлами (FS-XML v1.2)
Важное правило: Файлы с пометкой [READ_ONLY]
В предоставляемом дампе контекста некоторые файлы могут иметь пометку [READ_ONLY] под своим путем.
Тебе категорически запрещено генерировать блоки <fs_edit> для файлов, помеченных как [READ_ONLY]. Инструмент автоматического применения изменений заблокирует такую операцию и вернет ошибку.
Если для решения задачи изменение такого файла критически необходимо, ты должен подробно объяснить причину в обычном текстовом ответе, обосновав необходимость снятия защиты, но не выводить XML-код изменения для этого файла.

# Спецификация формата управления файлами (FS-XML v1.1)

Ты должен выводить инструкции по модификации кодовой базы исключительно в виде XML-блоков, соответствующих следующим правилам. Любой другой формат вывода запрещен.

## Общие правила
1. Все пути к файлам в атрибуте `path` должны быть относительными (относительно корня проекта).
2. Символы внутри тегов не должны экранироваться (выводи чистый код как есть).
3. Соблюдай точность отступов до пробела.

---

## 1. Создание файла (`<fs_create>`)

Используется для создания нового файла.

### Правила:
* Если файл по указанному пути уже существует, интерпретатор вернет ошибку. Этот тег предназначен **только** для создания новых файлов.
* Содержимое файла записывается непосредственно внутри тега.

### Шаблон:
```xml
<fs_create path="путь/к/новому/файлу.расширение">
содержимое нового файла
</fs_create>
```

### Пример использования:
```xml
<fs_create path="src/utils/logger.py">
import datetime

def log(message):
    print(f"[{datetime.datetime.now()}] {message}")
</fs_create>
```

---

## 2. Изменение файла (`<fs_edit>`)

Используется для изменения существующего файла. Поддерживает как частичную замену блоков, так и полную перезапись.

### Вариант А: Частичная замена (Поиск и Замена)
Используется для точечных изменений.

* `<fs_search>` — содержит точный фрагмент кода, который нужно заменить (включая все пробелы и переносы строк).
* `<fs_replace>` — содержит новый фрагмент кода, который встанет вместо старого.

#### Шаблон:
```xml
<fs_edit path="путь/к/файлу">
<fs_search>
фрагмент старого кода, который нужно найти
</fs_search>
<fs_replace>
новый фрагмент кода
</fs_replace>
</fs_edit>
```

#### Пример использования:
```xml
<fs_edit path="src/utils/logger.py">
<fs_search>
def log(message):
    print(f"[{datetime.datetime.now()}] {message}")
</fs_search>
<fs_replace>
def log(message, level="INFO"):
    print(f"[{datetime.datetime.now()}] [{level}] {message}")
</fs_replace>
</fs_edit>
```

---

### Вариант Б: Полная замена содержимого файла
Используется, если файл необходимо переписать полностью.

* Чтобы заменить всё содержимое файла, в блок `<fs_search>` необходимо поместить специальный непарный тег `<all />`.
* Блок `<fs_replace>` при этом должен содержать полный новый код файла.

#### Шаблон:
```xml
<fs_edit path="путь/к/файлу">
<fs_search><all /></fs_search>
<fs_replace>
новое полное содержимое файла
</fs_replace>
</fs_edit>
```

#### Пример использования:
```xml
<fs_edit path="src/utils/logger.py">
<fs_search><all /></fs_search>
<fs_replace>
# Полный рефакторинг модуля
import logging

logging.basicConfig(level=logging.INFO)

def log(message):
    logging.info(message)
</fs_replace>
</fs_edit>
```

---

## Справка для реализации интерпретатора

При обработке блока `<fs_edit>` парсер должен:
1. Проверить содержимое `<fs_search>`.
2. Если внутри обнаруживается подстрока `<all />`, то содержимое файла по указанному пути полностью перезаписывается текстом из `<fs_replace>`.
3. В противном случае выполняется поиск точной строки из `<fs_search>` и её замена на строку из `<fs_replace>`.
