Десктопный оркестратор (**Python + FastAPI + Vue 3 + PyWebView**) для превращения обычных веб-чатов с нейросетями в безопасных полуавтономных AI-агентов: контролируемая сборка контекста проекта и применение многофайловых правок в один клик по спецификации **FS-XML v2.0**.

---

## Зачем нужна эта программа?

### 1. Веб-чаты как полуавтономные AI-агенты с человеком посередине (Human-in-the-Loop)
Большинство разработчиков и так копируют код из веб-чатов (**Gemini, ChatGPT, Claude, DeepSeek, Qwen**). При этом нейросеть уже понимает структуру вашего проекта и вполне способна сама создавать файлы и точечно менять код — ей просто не хватает безопасного «моста» к диску.

В то же время полностью автономные AI-агенты в IDE несут две проблемы:
- **Сжигание токенов и самодеятельность:** агент сам решает, что читать, лазит по всему репозиторию, тратит миллионы API-токенов и может случайно переписать критичный код.
- **Работа «вслепую» по несколько часов:** автономный агент может долго вносить десятки правок, после которых проект просто перестаёт собираться или ломается бизнес-логика.

**FS-XML Interpreter** даёт вам полный контроль на каждом шаге:
- **Модульная изоляция:** вы сами выбираете, какие файлы и модули показать нейросети. Если у вас есть готовый модуль, который уже решает свою задачу — достаточно показать ИИ только файл с его экспортируемыми функциями/интерфейсами (или перевести критичные файлы в **`Read-Only`**). Что внутри этого модуля, нейронке даже знать не нужно — она спокойно напишет к нему новый модуль, не тратя контекст впустую и не рискуя ничего сломать.
- **Проверка на каждом этапе:** вы применили пакет правок одной кнопкой и сразу оцениваете результат: **запускается ли программа, корректно ли нейросеть вас поняла и не сломала ли логику**.

### 2. Веб-чат без ручного копипаста десятки раз
В веб-чатах огромные окна контекста без поминутных списаний за API-токены, но нет прямого доступа к файлам.
- В 1 клик соберите чистый **`context_dump.txt`** прямо в корень проекта (**ваш буфер обмена при этом не затирается**).
- Прикрепите файл в чат, а готовый XML-ответ нейросети вставьте в программу и примените все изменения за 1 клик.

### 3. Безопасность: Снапшоты, Откат и Копирование ошибки в 1 клик
- **Откат и повторное применение** по каждому файлу в истории SQLite с **детекцией ручных правок** (система предупредит, если вы правили файл руками после ИИ).
- **Быстрое исправление сбоев:** клик по ошибке в истории сразу копирует в буфер сбойный блок `<fs_search>` / `<fs_replace>` и актуальное содержимое файла с диска — остаётся просто вставить это в чат.
- **Снапшоты проекта:** контрольные точки отмеченных файлов и прав профилей перед крупным рефакторингом.

## Основные возможности (v2.0)

1. **Проекты и профили (разграничение зон ответственности):**
   - Ведение нескольких проектов, смена корневой папки и быстрое открытие папки проекта из верхней панели.
   - Независимые **Профили** под разные задачи (например, профиль `Backend` оставляет файлы фронтенда вне контекста — ИИ работает строго со своей зоной ответственности).

2. **Дерево контекста и просмотрщик прикреплённых файлов:**
   - Древовидная разметка файлов (`W` — `Writable`, `RO` — `Read-Only`) с поиском по подстроке, маскам (`*.ts`) и регулярным выражениям (`^src/`), а также массовой установкой прав.
   - Двухпанельный **просмотрщик прикреплённых файлов** с поиском и копированием кода.

3. **Умный дамп контекста (`context_dump.txt`):**
   - Сохраняется в `<корень_проекта>/context_dump.txt` без перезаписи буфера обмена.
   - Автоматический пропуск бинарных файлов (`[BINARY FILE EXCLUDED]`).
   - Опция **«Имена неотмеченных файлов»** — добавляет список путей (`UNMARKED PROJECT STRUCTURE`), чтобы ИИ знал о существовании остальных файлов, не читая их содержимое.
   - Опция **«Игнорировать тесты»** (`test_*`, `*_test`, `*.test.*`, `*.spec.*`) — исключает неотмеченные тесты из дампа, а в отмеченных оставляет заглушку `# [TEST FILE EXCLUDED - EXISTS ON DISK]`.

4. **Двухуровневый игнор (`fsignore`):**
   - Глобальный (`fsignore_global`) + проектный (`.fsignore`) с синтаксисом `.gitignore`, поддержкой inline-комментариев `#`, экранированного `\#` и динамической перезагрузкой.
   - Исключает из сканирования и дампа тяжёлые папки вроде `node_modules/`, `.venv/`, `.git/`, `dist/`.

5. **Надёжный парсер FS-XML v2.0 и песочница (`Sandbox`):**
   - Команды `<fs_create>` (запрещает перезапись существующих файлов) и `<fs_edit>` (несколько пар `<fs_search>`/`<fs_replace>`, толерантность к хвостовым пробелам, сохранение `CRLF`/`LF`, полная перезапись через `<all />`).
   - Защита от выхода за пределы корня проекта (`Path Traversal`), проверка прав доступа к каждому файлу и CORS-фильтр локальных источников.
   - Расширяемый реестр обработчиков (`BaseCommandHandler` + пользовательские команды в `core/handlers/custom/`).

6. **Снапшоты и переносимая конфигурация (`fs_orchestrator_config.json`):**
   - Создание и восстановление снапшотов для текущего или всех профилей проекта.
   - Экспорт и импорт `fs_orchestrator_config.json` для переноса проекта, профилей и разметки файлов на другой ПК.

7. **Десктоп-интерфейс и персонализация:**
   - Изменяемые по ширине и сворачиваемые панели, сворачиваемый системный лог, встроенная модалка **«Инструкция»**, включение/выключение и смена фонового изображения.

## Быстрый старт

### Запуск готовой программы
Ничего устанавливать, компилировать и настраивать не нужно — скомпилированный лаунчер **`FS-XML.exe`** уже лежит в корне проекта и в релизной сборке (`release/FS-XML.exe`):

1. Скачайте релиз (или клонируйте репозиторий).
2. Запустите **`FS-XML.exe`**.

## Рабочий процесс (Workflow)

```
[ Проект на диске ] ──> (Разметка W / RO в профиле) ──> [ Создать context_dump.txt ]
                                                                   │
                                                                   ▼
                                                  [ Дамп + Промпт в чат с ИИ ]
                                                                   │
                                                                   ▼
[ Проверка человеком ] <── (Кнопка "ВЫПОЛНИТЬ ЗАМЕНУ") <── [ XML-ответ нейросети ]
         │
         ├──> Ошибка патча?  ──> [ Клик по ошибке в истории ] ──> (Копия поиска + файла с диска)
         └──> Не та логика?  ──> [ Откатить / Повторить ] или [ Загрузить снапшот ]
```

## Советы по работе с нейросетями

1. **Передайте системный промпт один раз:**
   Нажмите **«КОПИРОВАТЬ ПРОМПТ»** (берётся из `FS-XML.txt`) и вставьте текст в **System Instructions** (Google AI Studio, API, Custom Instructions) или отправьте первым сообщением в чат.
2. **Вставляйте ответ нейросети «как есть»:**
   Неважно, оборачивает ли ИИ XML в блоки markdown или пишет пояснения вокруг тегов — скопируйте весь ответ целиком и вставьте в центральное поле. Парсер сам извлечёт валидные команды.
3. **Если возникла ошибка `Search block not found`:**
   Нажмите на строку с ошибкой в правой панели истории — в буфер сразу скопируются сбойный блок и актуальный код файла с диска. Отправьте их ИИ для исправления.
4. **`<fs_create>` только для новых файлов:**
   Существующие файлы редактируются только через `<fs_edit>` (для полной перезаписи используется `<all />`).
5. **Следите за чистотой контекста в чате:**
   При отправке свежего `context_dump.txt` удаляйте старые дампы из переписки или начинайте новый диалог, чтобы модель не путалась в устаревших версиях файлов.

## Формат команд FS-XML v2.0

### 1. Стандартные команды (разрешены всегда)

#### Создание нового файла (`<fs_create>`)
```xml
<fs_create path="src/utils/logger.py">
import datetime

def log(msg: str):
    print(f"[{datetime.datetime.now()}] {msg}")
</fs_create>
```

#### Точечное редактирование (`<fs_edit>`)
Внутри одного блока `<fs_edit>` поддерживается сразу несколько пар `<fs_search>` / `<fs_replace>`:
```xml
<fs_edit path="src/utils/logger.py">
<fs_search>
def log(msg: str):
    print(f"[{datetime.datetime.now()}] {msg}")
</fs_search>
<fs_replace>
def log(msg: str, level: str = "INFO"):
    print(f"[{datetime.datetime.now()}] [{level}] {msg}")
</fs_replace>
</fs_edit>
```

#### Полная перезапись файла (`<all />`)
```xml
<fs_edit path="config.py">
<fs_search><all /></fs_search>
<fs_replace>
DEBUG = True
DATABASE_URL = "sqlite:///app.db"
</fs_replace>
</fs_edit>
```

---

### 2. Управляющие команды (требуют флага «Управляющие команды»)

#### Что они делают и зачем нужны?
Это команды, с помощью которых нейросеть может **автоматически управлять организацией вашего контекста**: создавать новые профили и менять права доступа к файлам (`Writable` / `Read-Only` / `Unmarked`), чтобы вам не приходилось вручную перекликивать десятки файлов в дереве.

*Пример:* вы просите ИИ: «Выдели отдельный профиль под задачу авторизации, переведи старые конфиги в Read-Only, а новые роутеры сделай Writable» — модель сама перенастроит рабочую область за один ответ.
Примечение- Изменение прав на файлы влияет только на текущий активный профиль. У ИИ нету команды сменить активный профиль.

#### Как они работают и на что влияют?
- **Защита по умолчанию:** пока галочка **«Управляющие команды»** в правой нижней панели **выключена**, оркестратор **блокирует** любые управляющие команды с ошибкой доступа (при этом обычные `<fs_create>` и `<fs_edit>` в том же ответе продолжают выполняться).
- **Когда флаг включён:**
  - изменения применяются в рамках текущей сессии и **сохраняются в базе данных SQLite**;
  - обновлённые права сразу отображаются в дереве файлов и будут использованы при **следующей генерации `context_dump.txt`** и при дальнейших проверках записи в песочнице.
- **Важно:** управляющие команды меняют **метаданные профилей и прав**, а не содержимое файлов на диске (поэтому откат по ним в истории не предусмотрен).

#### Какие команды бывают?

1. **`<fs_profile_create>` — создание нового профиля:**
   Создаёт новый профиль конфигурации в текущем проекте (если профиля с таким именем ещё нет).
   ```xml
   <fs_profile_create name="Backend-Focus" />
   ```

2. **`<fs_file_state>` — изменение статуса файла в текущем профиле:**
   Устанавливает одно из трёх состояний (`writable`, `readonly` или `unmarked`) для указанного файла:
   ```xml
   <fs_file_state path="src/config.py" state="readonly" />
   <fs_file_state path="src/api/routes.py" state="writable" />
   <fs_file_state path="src/legacy/old.py" state="unmarked" />
   ```
   - `writable` — включить файл в контекст и разрешить ИИ его изменять;
   - `readonly` — включить файл в контекст строго для чтения (защита от правок);
   - `unmarked` — убрать файл из активного контекста профиля.

*(Дополнительно система поддерживает пользовательские команды через `BaseCommandHandler` в `core/handlers/custom/`.)*
